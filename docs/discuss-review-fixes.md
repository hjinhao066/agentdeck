# 「讨论一下」MVP 审查返工说明

本说明对应本机 `mvp-review.md` 对原 MVP 的逐项意见，设计依据仍为 `design-v2.md` 的自动编排 MVP 及用户随后拍板的调整。说明当前源码的处理和能力边界，不代表现役安装已更新，也不代表真实账号、浏览器或物理 Windows/Mac 已完成联调。队长操作见 [discuss.md](discuss.md)。

## 严重问题

### S1：脱敏不应改坏共同题目与论据

`discussion-privacy.js` 的 IPv6 先匹配候选再用 Node 的 `net.isIP` 核验完整地址，时间 `10:30:45`、比例 `3:2:1` 与 `std::vector` 不再因冒号被改写。裸域名限于常见真实 TLD、私有主机后缀及明确的内部主机字段，避免把 `console.log`、`fs.readFileSync`、`user.profile.name`、`discussion-core.test.js`、`app.config.ts` 当作域名。不能据此声称所有私人公网域名都能识别。

凭据扫描不再删除含 `token:`、`secret =`、`key: value` 的整行：保留讲解、占位符和类型示例，以及未展开的 `process.env.API_KEY`、`$TOKEN`、`config.clientSecret` 等明确代码引用，只对识别到的凭据做替换并返回硬拦标记；真实带引号的值和已知密钥格式不借引用豁免。用户名不再按普通单词全替换，处理明确用户名字段及用户路径；因此常见单词 `root`、`node` 和普通叙述不会无差别消失。

普通公开可核查的 http(s) 引用原样保留，内部主机、IP URL、带私人标识的查询字段和真实凭据 URL 分别脱敏或硬拦。URL 路径里的 UUID、已知会话 ID、邮箱、用户目录及明确身份字段会使整条网址脱敏，避免改写路径后产生「仍可核查」的假象；扫描支持常见百分号及嵌套编码，编码凭据仍硬拦，畸形编码也不能隐藏其他 ASCII 凭据。年份、任意散列和普通 token/password 教学路径保留。这是对「隐私标识脱敏」与「来源保持可核查」的明确取舍，不抹掉所有引用再让互评者凭印象判断。私人背景组合和无法可靠识别的文本在 `limitations` 中说明。正反两类回归集中在 `tests/discussion-privacy.test.js`。

### S2：导出元数据容错，并保留可用答案

`discussion-core.js` 对 Markdown 导出做定位映射，容忍标签/JSON 下划线转义、代码包裹及标签后的文字。只移除识别到的协议元数据，保留完整正文，不把整篇导出稿重新格式化。

解析不到、字段缺失或协议无效时，作业进入 `metadata-needed`，保存原答、实际型号证据与同一次 attempt。队长可用 `resume --metadata-file ABS --job JOB` 补 JSON；补录仅接受讨论协议字段，不能改写实际模型证据，不重新发送题目、不再次消耗模型调用。补录必须依据原稿，不能编造分歧或忠实性判断。原稿中若有凭据，元数据补录也不能绕过隐私硬闸。

### S3：区分前台自检异常与未完成请求

当前基础网页执行器具有 `f8a3580` 所修复的完整导出保留行为；讨论适配层另外识别 `FRONT_UNSURE/FRONT_STOLEN`，本轮不改网页执行器的那段自检逻辑。

`FRONT_UNSURE` 仅在完整报告与 meta 可核验时保留答案，不把「无法判定前台归因」当作答案不存在。`FRONT_STOLEN` 仍是异常：完整稿保存到磁盘，讨论暂停并标明 `answerSaved`，普通恢复不会自动继续使用。队长核对原稿、确认后台工具行为已修复后，显式 `resume --accept-saved` 接回保存的原答案；这不是重复提问，也不是确认按钮替代了实际修复。没有完整稿或证据不足仍保持待处理。

## 中等问题

### M1：恢复租约避免 PID 复用与残留守卫

执行器租约记录 PID、进程启动身份和心跳，不再只以 `kill(pid, 0)` 判断同一执行器。Linux 使用 boot ID 与进程启动字段，macOS 使用进程启动时间，Windows 使用进程创建时间。无法核实一个仍活着的现有 owner 时保守保留，不抢它的工作。

新租约先在唯一 claim 目录写完整 owner，再原子改名成为有效锁；不再创建缺 owner 的最终锁，也不再用可能永久残留的 `.runner-recovery` 守卫。陈旧租约按旧代次留确定性 tombstone，防止两个恢复者拿旧观察替换刚生成的新租约。旧格式 PID 锁需核对实际 runner 与讨论 ID；损坏或不可核实的旧锁不假装安全可抢。恢复仍要求同一原讨论 ID，不重建整场。

### M2：区分未发送与可能已发送，明确显示恢复阻塞

`mayHaveSent` 贯穿请求落盘、网页诊断和失败状态。参数/材料校验在发送前进行；确定未发送的登录、工具、校验或排队失败可定向续跑，不要求先确认一个不存在的网页请求。安全成员可以恢复，另一位状态不明的成员不会把这一批全部拦住，但全体有效稿齐之前不会冻结或进入下一轮。

运行中限流、超时、崩溃或提交意图不明仍保守视为可能已发送；额度恢复本身不证明旧请求已结束。`resume` 返回 `resumedJobs` 和 `resumeBlocked`，列明哪些真正恢复、哪些需要导入原稿、补元数据或确认旧请求结束。明确核对旧生成、关闭保留页并处理 pending 后，才可 `--retry JOB --confirmed-ended JOB` 创建新 attempt，不暗中重问。

### M3：保留独立后台通路，明确其调度边界

本轮保留直接后台 `claude --print` 与独立 `createExecutor` 的运输层，以满足「队长立刻从源码使用，同时不重启现役应用」。没有把它说成已完整接入应用的 `new/tell` 派活及会话调度。

因此讨论参与者不进入 `ledger/peek`、侧栏会话和应用会话并发额度；队长用 `discuss status/wait` 管理讨论，另行考虑自己同时派出的订阅任务。网页仍受同一技能的账号锁、冷却和 pending 保护，确认未发送的 `LOCKED/COOLDOWN` 在后台等待条件，不绕过锁、不抢前台。这是有期限的发送等待，不能宣传为已经共用应用内 FIFO。

讨论结论通过受队长权限保护的 `main-discuss-receipt` 进入普通待回执队列，按稳定 ID 去重并拒绝过期投递；用现有同步配置保存接口落盘成功后才确认收到，写盘失败保留执行器回执待重投，重投不重复入队。旧应用不支持该动作时保留 `receipt.json`，队长用源码 `wait` 取回；换班使旧令牌失效也不丢结果。后续接入完整会话调度属于另一个明确范围。

### M4：忠实性核对仍是自述，不宣传为独立核验

汇总提示继续要求逐份核对、保留最强少数派及适用条件；已记录少数派非空而汇总数组为空会阻止完成。但数组非空并不证明某条异议真的进入了正文，`faithful=true` 也不证明事实正确。

产物明确记录核对来源及 `externallyVerified=false`。默认 Opus 既参与又汇总，不是独立裁判；队长补录协议字段也不自动获得外部验收资格。文档和回执将其表述为模型自报/补录，保留 MVP 的能力边界。全员确认或外部证据核查不在默认调用预算里。

### M5：去明确作者归属，保留客观品牌事实

正文去掉模型/作者/Provider 签名行、独立品牌署名、明确自述身份和 `By Claude`、`ChatGPT 认为` 等归属。分歧及少数派元数据同样先匿名，再参与出站脱敏。稳定 A/B/C 代号只在本机映射；每位评委独立以无偏洗牌获得同一冻结轮的材料顺序，排列记录随输入存档。

客观产品、公司名称及公开引用不无差别替换。例如题目本身比较 Claude 与 OpenAI 产品，删掉正文品牌会再次重演 S1 的曲解。无法证明自由公司名就是作者时保留它；模型也可能认出自己的行文。因此这仍是流程匿名，不是全文本匿名或严格双盲。

### M6：网页与每次执行都有外层期限

CLI 单次、网页工具进程的外层期限为 30 分钟，未发送网页的锁/冷却等待也有期限。后台 runner 每次启动执行、以及用户明确 `resume` 后的执行预算为 60 分钟，包含各轮与排队等待；它不是创建讨论后的永久累计期限，续跑不会被误写成「原一小时内已完成」。

到期中断执行并保留原稿，可能已发送的作业保持待处理，不用超时代表共识或任务成功。取消同样停止后续派发；即使外部执行器不及时响应也不会无限占着整场。技能保留的请求页及 PENDING_REQUEST 仍需核对和处理，杀本机工具进程不等于服务端生成已经结束。

### M7：帮助随安装工具提供，交接只留必要私有索引

队长简报保留发起、状态、等待、恢复、取消和 unknown 确认规则，并提供 `discuss help`。说明随安装工具目录拷贝，帮助不依赖队长当前工作目录中的仓库相对路径。

新版本接力交接读取本机未完讨论索引，只带 ID、状态和轮次，不把题目、参与原稿或长答案塞进交接上下文。旧应用仅配合源码 CLI 试用时，原 `briefing/handoff` 不会因此自动更新；接班者需主动用源码 `discuss status/help`，不能宣称现役应用已升级。

原先为容纳新行而缩短的四条既有队长规则恢复，本轮不借讨论功能改写已有工作规约；按当前 1.6 基础的 10000 字符简报约束检查新内容，不沿用原审查基线的 8000 字符假设。

## 轻微问题及联调边界

### L1：恢复网页稿核对提交、导出和模型证据

`recoverWeb` 不只看文件是否存在：拒绝错误 meta 状态，要求 `submitted=true`、有效 `finishedAt`、支持的 `exportMethod`，再核对普通 chat、实际 6 Pro 和 Pro 档位，以及可读非空的完整报告。缓存结果恢复时重新核对网页产物，并要求正文与先前保存稿一致。缺证据保持待处理，不借恢复放宽模型标准。

### L2：Windows CLI shim 解析不依赖 shell

Windows 按 PATH 查找原生执行文件或 npm `.cmd/.bat` shim；将 shim 当文本读取，只接受其同目录下存在的受限 Node 入口，然后以 Node 直接执行。不会把任意 batch 内容交给 shell，也不通过插值命令启动。不能安全解析就 `TOOL_UNAVAILABLE`，明确未发送，允许处理后恢复。代码级假 shim 回归不等同于实际 Windows 桌面安装已验证。

### L3：可选 Gemini 未经真实账号联调

可选 `agy` 仍请求 `gemini-3.8-flash-high`，检查 Antigravity 订阅快照及 Gemini 额度，并保留实际输出型号/档位证据。当前实现与用例覆盖不代表已向真实 Gemini 账号发题；本轮未获真实 CLI/网页请求联调授权，不发请求、不消耗额度。账号状态文件形状、当前厂商输出与实际可用型号仍需授权后的实际联调，失败时暂停，不换弱模型。

### L4：固定长度回执 ID，长期索引防重放

讨论回执 ID 改为 `dr-` 加 SHA-256，固定 67 个字符，自定义长讨论 ID 不再导致回执验证静默失败。原讨论 ID 仍在私有产物和结论中可追溯。

队长配置中的已接收 ID 保留为小索引，避免旧回执在换班、重复 `wait` 或重新投递时再次进入队列。它仍会随历史增长；本轮不任意淘汰，否则会失去旧回执防重放保证。索引不保存原稿或敏感凭据。

### L5：凭据命中硬拦，原文仅留本机私有目录

新题目、每轮原始答案和分歧元数据命中已知凭据时返回 `blocked=true`，讨论标记 `privacy-blocked`，不冻结该轮、不产生后续提问。不能先用占位符替换，再重扫无凭据的副本来绕过硬闸；应清理材料后新建讨论。网页技能的检测是额外防线，不代替协调器的硬拦。

原题、原稿、`run.json` 和私有映射可能仍含原始敏感信息，目录/文件权限为 0700/0600，放在本机 `~/.agents-state/agentdeck/discussions`，不进入共享看板、技能 Git 同步或公共仓库。Windows 依赖本机目录权限，不宣称 POSIX chmod 可充当 Windows ACL 验证。事件与扫描结果只记类别、状态和必要关联，不打印秘密正文。

### L6：无偏洗牌

作者代号与各评委的冻结材料顺序使用 Fisher–Yates 和 `crypto.randomInt`，移除随机比较器排序的偏差。同一方案代号在场内稳定；每次派发的排列持久化，恢复不重新洗掉已发送输入，也不把同轮刚交的稿塞给后来回答的人。

## 原漏检清单与仍有的限制

| 类型 | 本轮处理 | 边界 |
|---|---|---|
| `sk_live_`、`xoxb-`、`ya29.`、既有 sk/gh/JWT 等已知格式 | 凭据硬拦，安全副本不保留原值 | 真实格式变化仍需更新规则；教学占位符不伪装成真实凭据 |
| `aws_secret_access_key` 无冒号/等号 | 明确字段后的长值硬拦 | 无字段的一段随机文本不能可靠判定其用途 |
| 数据库 URL 用户名/密码、真实凭据查询参数或路径 | 在 URL 保护公开引用前识别并硬拦 | 不通过先当邮箱替换来泄漏 userinfo；普通示例值与真实值不可完全判别 |
| 电话、18 位身份证、用户目录和 `/var/root` | 识别常见结构并脱敏 | 地区格式、非标准写法与无上下文私人背景无法保证全覆盖 |
| 明确姓名/联系人、住址/地址字段 | 处理标注的值，保留其他约束 | 不对普通中文词句或地域叙述做全字通配猜测 |
| 单独长十六进制/Base64 串 | 不凭长度删掉任意散列、代码或公开资料 | 未标注密钥仍可能漏检，`limitations` 明确说明；材料准备者须剔除不应外发内容 |
| 公共证据 URL 与内部主机 | 保留普通公共链接，处理内部主机/IP/明确私人字段；路径含 UUID、已知会话 ID、邮箱、用户目录时整条脱敏，编码凭据仍硬拦 | 未标注的私人公网主机、无法识别的路径背景仍需人工识别，不凭年份或任意散列猜身份 |

这些限制不是静默降级或放行敏感材料的理由；它们说明自动规则的判断范围。测试用假 CLI/网页、协议稿与独立私有测试目录验证故障路径，不代替真实账号运行、性能对比或讨论效果评估。提示词来源继续保留 [agent-council](https://github.com/yogirk/agent-council)、[Council Plus Advisors](https://github.com/jacob-bd/llm-council-plus) 与 [Ensemble](https://github.com/raiyanyahya/ensemble) 的 MIT 改编说明。
