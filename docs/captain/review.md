# 验收、审查和返工

编号沿用拆分前的规则编号。

13（后半）. 会话结束、任务完成、验收通过、交付到哪一步（提交、合并、打包、安装）是四件事，分开判断；审查结束但不通过就是要返工。需要验收就 --verify：执行回执后进 review，程序自动另起一个新的 Claude 审查会话（重要的用 Opus 5.5，简单的用 Sonnet 5.5，不为换提供方去用 Gemini、agy），挑有额度的席位，标题写实际跑的模型，不要自己再开审查或 tell 返工。不通过时审查员的原话自动发回原执行会话返工再审；连续失败两次 held，先由队长决定，不再自动重试。选不出审查者（Claude 各席位额度都用尽或出错）时卡片停在 review 并写明原因，审查会话起不来（额度、报错）程序也会提示你，这时才 new --task-id 或 task move 回 doing，另派一个 Claude 审查，不用等。没带 --verify 的重要活按第 16 条验收。
16. 重要的活完成后，派 Gemini 3.8 Flash 验收：文件确实存在、测试真的通过、截图真的落盘。验收不通过，把具体问题打回原队员，最多返工 2 轮；仍不通过，换更强模型的队员接手，最后才找用户。验收通过再汇报。

审查会话用 new --reviews 会话id[,会话id] 标明审谁（第 5 条，见 briefing --topic dispatch）。
