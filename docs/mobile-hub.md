# 手机总台（`mobile-web/hub/`）

一组静态文件（`index.html`、`core.js`、`app.js`、`style.css`、`machines.json`、PDF 阅读用的两个 pdf.js 文件，版本更新页的 `releases.js`，以及构建时从仓库根目录带上的 `release-notes.json`），部署在手机入口的根路径。页面本身没有数据和密钥，只同源请求每台电脑自己的前缀（`/mac/…`、`/win/…`），接口契约见三端方案 2.2 节。旧的 `mobile-web/` 不变，继续供本机直连和回滚。

正式发版由 `scripts/release.js` 自动构建并部署总台，公网版本核对失败则回滚并标红；随时运行 `npm run mobile:check` 与本机安装版比对。见 [部署与版本核对](mobile-release.md)。

## 行为

- **五种状态**：先请求无需登录的 `api/info`：200＝新版，再请求 `api/snapshot`（200＝在线，401＝需要登录）；`api/info` 返回 401 或 404＝旧版，显示「需要升级」，不出登录框。两个请求都适用：502 加 `{"offline":true}`＝离线；8 秒超时＝无响应（可能在睡眠）。机器在线期间不再重复探测，快照失败后下一轮重新探测。契约以外的结果（其他状态码、不带 `offline` 的 502、手机断网）显示「连接异常」，同样不能派活。
- **派活**：每条消息只发往「发给」里选中的那台电脑。两台都在线时默认 Mac；顶栏选了某台电脑，目标跟着变。目标离线、无响应、未登录、需升级、队长未启动或队长终端已退出（总览写「已退出」，和电脑一样）时，发送按钮禁用并写明原因，**不会改发另一台**；电脑因为没有在运行的队长而拒收（409）时，失败的消息下面写出电脑给的原因。发送失败的消息留在对话里，点铅笔放回输入框，点重发图标原样再发，点叉关掉。`api/info` 带 `send-dedupe` 的电脑：发队长的消息带 `deduplicationKey`、等 15 秒，超时写「没连上 某电脑……点右边的重试」，重试不会让队长收到两遍；旧版电脑不带 key（它会拒收不认识的字段），仍是 8 秒和「可能已经排队，先看一眼对话」。
- **发出的消息一直在**：点发送后你的气泡立刻出现，下面一行小字写「发送中…」，电脑收下后变成「已发出，等 Mac 队长接收」（队长正忙时写「忙完手上的就会看到」）。桌面端要等队长空下来才把消息打进去，这中间可能隔几分钟；气泡一直留着，等电脑自己的对话记录里出现这条，就由那条原位接替，不闪、不重复（`core.js` 的 `settleOutbox`，按发送时已有的回合区分同样内容的旧消息）。发送中只禁用发送键，输入框不锁（锁了会把手机键盘收起来）。刚发出的内容原样再点一次发送，不会再发，输入框下方提示「刚才那条已发出」；几秒内再点一次才真的再发。这些都只在内存里，重新加载页面后以电脑的记录为准。
- **输入栏贴底**：页面本身不滚动（`html`/`body` 固定、`overscroll-behavior: none`），只有对话等列表在里面滚。外壳高度取 `visualViewport` 的高度并跟随它的偏移（回退 `100dvh`），软键盘弹出时输入栏贴在键盘上方、底部导航隐藏；手指拖在不能滚的地方或列表尽头时不带动整页（`core.js` 的 `dragMovesPage`）。单机页是同一套做法。
- **不跟随跳转**：总台所有 `fetch` 都带 `redirect: 'error'`。某台电脑（或入口）返回 3xx 时请求直接失败，按「连接异常」处理，不会被带到另一台电脑，更不会带着 cookie 或重发 POST。入口本身也会把前缀下的 3xx 换成 403，两层各自挡。
- **登录**：每台电脑各自登录，token 只用 JSON POST 发往该电脑的前缀，页面不保存。退出一台不影响另一台；退出类图标要点两次。
- **本地存储**：只有主题、所选电脑，以及每台电脑的元数据（最后在线时间、会话数、干活数、队长状态、主机名、版本）。对话、回执、输出、看板和草稿都不落盘。
- **轮询**：页面可见时，选中的电脑每 5 秒、其余 15 秒、连不上的 30 秒；刷新按钮立即拉取全部。
- **顶栏电脑切换**：电脑状态不再单独占一行，也没有输入框上方的「发给」栏。顶栏里每台电脑一个小圆点加名称（点亮＝在线，空心＝离线，黄＝需登录/无响应/需升级，红＝异常；完整状态在悬停提示和读屏名称里）。总览、会话、看板里它选「看哪台」，带「全部」；队长页里它选「发给哪台」，没有「全部」，选哪台就只发哪台。输入框下方的提示行平时不显示，只在发送中、已排队、或发不出去（写明原因）时出现。360 宽以上顶栏仍是一行 52px；更窄的手机把切换放到第二行，不截断名称。
- **对话只有一来一回**：桌面端为每次注入存一条「回合」（你的消息、每张派活卡、每次回执送达）。总台和单机页用同一套规则（`core.js` 的 `groupTurns`，有单元测试）折成：右边一个你的气泡（鲜绿色），左边一个带皇冠和「Mac 队长」名字的回复气泡，气泡随文字长短伸缩。派活卡、回执、通知、工具步骤都**不显示**；队长只派了活、没说话的那一轮，左边什么都不出现。回复下方有复制图标；超过 500 字或 10 行的消息折叠，点「展开全文」看全文。总台不显示图片，只写「附 N 张图片」。
- **只留队长说的话**：桌面端的回复是从终端屏幕上读出来的，会夹带终端残留。`core.js` 的 `cleanReply` 逐行去掉：`❯` 开头的输入回显（连同能对上你原话的折行）、回复开头那段其实是你这一条消息结尾的回显（队长还在干活时发的消息，取屏会从回显中间读起，前面没有 `❯`；只有一直对到这条消息末尾、且不少于 8 个字的开头几行才算）、AgentDeck 自己注入的提示（新回执、清空上下文、读看板继续、永动机轮换）、`Read 1 file, ran 3 shell commands` 这类工具小结、`Background command "…" completed`、文件 diff 的行号尾巴、`Update available!`、`N new messages (click) ↓`、启动图案等。拿不准的行一律保留：宁可多一行终端字，也不丢队长的一句话。
- **对话区占屏幕约八成**：队长页没有标题行（电脑在顶栏切换里选），输入框是一行、随草稿长高（最多约 5 行），有草稿时才出现清空图标；底部标签栏压到 53px。390×844 的手机上对话区约 681px（80%）。
- **额度表格**：每台在线电脑的总览卡里有「额度」表：每个账号一行，5h 与每周两列（剩余百分比、重置时间、细进度条），队长在用的带皇冠；用尽、数据过旧、读取失败都用文字和图形标出，不只靠颜色。点一行在原处展开账号（已脱敏）、来源、采样时间和两个窗口的确切重置时间。数据来自该电脑自己的 `<前缀>api/quota`，最多每 30 秒读一次（点刷新立即读）；读失败时保留上次的行并标「未能更新」，旧版没有这个接口（404）则不显示表格；额度不写入手机存储。
- **切换队长的账号**：每台在线电脑的总览卡里有一行「队长在用 Claude US · 5 小时剩 72%」和「切换队长」；队长页顶部也有一条。点开是底部面板：
  只列这台电脑的账号，各自的 5h / 每周剩余，队长在用的带皇冠，额度用尽、快用完、没登录的置灰并写明原因（可聚焦，读得到原因，点了没反应）。
  选好后再问一次，点「确认切换」才发 `POST <前缀>api/relay`；之后显示「正在切换」「已换到…」或「没有换成」加原因，成功后自动连到新队长。
  面板从打开起只对这台电脑发请求，另一台不受影响。旧版没有这个接口（404）、离线或没有队长时不显示入口。数据不写入手机存储。详见 [mobile-web.md](mobile-web.md)「手机上切换队长的账号」。
- **设置 · 临时拉满**：电池供电、电池模式开着时，设置卡片最上面是「临时拉满」框：选时长（直到取消 / 2 小时 / 今天 23:59，记住上次的选择），点主按钮「临时拉满」就发 `POST <前缀>api/battery`（`{boost:true, boostMinutes?}`），电脑在电池下也按正常并发上限放行，省电模式本身不变。拉满后框里写「已临时拉满（到 HH:MM / 直到取消或接电源）」，右边 × 图标按钮取消（`{boost:false}`）。接上电源、到时间或电脑上取消后，卡片下一轮读到就跟着变；接着电源或模式关着时写明「本来就不限制，不需要拉满」并不给按钮；旧版（返回里没有 `boost`）不显示这个框。
- **设置（电池模式）**：顶栏的齿轮图标（平板横放时在侧栏底部）打开设置面板，每台电脑一张卡片。电池模式用「自动 / 关」两档（自动＝没插电时限制同时干活的会话数，关＝不限制），电池并发上限用 − / + 图标按钮调（1–10，到头禁用）。点一下就发 `POST <前缀>api/battery`（只带 `mode` 和/或 `cap`），电脑立即生效并写回它的配置，面板再显示电脑返回的数；连点 + 的几下合并成一两次请求。卡片里一句话写明现在是电池还是接电、实际同时最多开几个会话、几个在干活。面板打开期间每轮轮询重读，电脑上改了这里会跟着变。电脑离线时写明并且不给控件；旧版没有这个接口（404），写「AgentDeck 还是旧版，更新到新版后才能在这里调整电池模式」，同样不给控件。改失败时用文字说明原因并回到电脑原来的值。设置不写入手机存储。
- **看板**：按卡片 `updated` 合并两台的结果，用 `dispatch_claim.owner` 对主机名标出领取的电脑；卡片里的文件路径向领取它的电脑要，没有领取记录时向显示的那份所在的电脑要。
- **待我处理**：合并在线电脑的待办事项与结果汇报；每条回复只交给该条所在电脑的队长，并带原事项上下文，成功后自动打勾归到默认折叠的「已完成」。失败原因在原条目显示，草稿保留。详见 [待我处理](attention.md)。
- **待办**：底部的待办标签。顶部输入框（滚动时留在上面），回车或加号图标记下；圆圈勾掉/放回，已完成折叠。两台电脑的 `api/todos` 按 `updated` 合并，
  删除标记会盖住旧副本；这个标签不显示电脑切换。记和勾只发给一台：在别的标签里选过的那台（没选过就是默认的 Mac），不在线才发给另一台，勾选带上 `base`
  以便另一台刚记的那条也能勾。打开标签时每次轮询都读，平时每 30 秒读一次（给标签上的数字）。旧版电脑（404）提示需要升级。
  点这个标签时光标直接进输入框。总台记住上次停留的标签（`agentdeck-hub-view`），网址带 `#todo` 等标签名时直接打开那个标签。
  数据不写入手机存储。详见 [todo.md](todo.md)。

- **Markdown**：队长回复、回执、看板回执、「待我处理」的细节和预览的 .md 文件用同一个渲染（`core.js` 的 `renderMarkdown`，桌面端 `chat-core.js` 也调用它）：表格（窄屏在自己的框里横滑）、加粗、斜体、删除线、标题、有序无序和嵌套列表、引用、行内代码、带复制图标的代码块、分隔线、链接。输出先转义，再按白名单拷进页面，脚本和其他标签都进不来。流式输出到一半的表格（分隔行还没出来）也按表格画。
- **平板横放（≥900×600）**：照搬桌面端结构：左侧栏（队长、待我处理、任务看板、待办、总览；每台电脑的队长和挂在下面的队员；底部额度和刷新/主题/退出），中间是页面，≥1180 宽时右边是文件预览栏；底部标签栏不显示。对话保留手机样式，顶上的「队长在用」条保留。看板按状态分列。侧栏可收起。手机宽度下完全不变。
- **版本更新与每日进展**：总览最下面一行「版本更新」（写着这台电脑的版本号和几件待你定），平板横放时点侧栏底部的版本号。页面从上到下：每日进展卡（大数字是当天完成的卡，下面最近几天的柱子和左右箭头切换日期，再下面返工、审查不通过、等你决定、交付和各项目完成数），然后是所有版本（计划中和已发布）按时间从新到旧排在一条线上。版本内容来自和总台一起发布的 `release-notes.json`、由 `releases.js` 画（桌面面板用同一个文件），不向电脑请求；每日进展向默认电脑（Mac）要 `api/progress`，打开页面时读、之后最多每分钟一次，旧版电脑（404）在卡片里写「还是旧版」，连不上写明原因，其余内容照常。每台电脑在用的版本标在对应那一版旁边。复制图标把一版内容复制成纯文字。
- **文件和链接预览**：见 [mobile-web.md](mobile-web.md)「文件和链接预览」。

## 增删电脑

改 `machines.json`：`id` 为小写字母数字，`basePath` 必须是 `/<id>/`，`default: true` 的那台是默认派活目标。

## 本地试用和测试

```
node tests/fixtures/hub-proxy.js          # 假的 Caddy 加两台假电脑，打印地址和测试 token
node --test tests/mobile-hub.test.js
AGENTDECK_HUB_SCREENSHOT_DIR=<目录> npx playwright test tests/e2e/mobile-hub.spec.js --workers=1
```

`tests/fixtures/hub-proxy.js` 只在本机 loopback 上运行，不连接真实的 AgentDeck、VPS 或共享看板。
